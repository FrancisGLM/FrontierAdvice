RESUMEN DE IMPLEMENTACIÓN: PANEL DE ADMINISTRACIÓN Y AUTENTICACIÓN
=====================================================================
Fecha: Junio 2026

Este documento resume los componentes, rutas y estructura que se crearon en el frontend para soportar el inicio de sesión y la vista de administrador. Esto te servirá de base para conectar o extender tus flujos en n8n y Strapi.

1. AUTENTICACIÓN (LOGIN)
---------------------------------------------------------------------
- Estrategia: Se utiliza el plugin "Users & Permissions" nativo de Strapi.
- Endpoint de Login: El frontend realiza una petición POST a `http://URL_STRAPI/api/auth/local`.
- Parámetros enviados: `identifier` (usuario o email) y `password`.
- Almacenamiento (Contexto): Al loguearse correctamente, el servidor Strapi responde con un token `jwt` y un objeto `user`. El frontend (mediante `AuthContext.tsx`) guarda ambos valores de forma persistente en el `localStorage` del navegador web.
- Ubicación Visual: El botón para abrir el modal de inicio de sesión se encuentra oculto al final de la página `/configuracion`, en la sección "Administración".


2. RUTAS Y COMPONENTES PROTEGIDOS
---------------------------------------------------------------------
- Barra Lateral (NavRail.tsx): 
  - Solo si existe un usuario logueado en el `AuthContext`, se inyecta un nuevo botón llamado "Panel Admin" (icono de escudo) en el menú principal.
- Página Protegida (/admin/page.tsx): 
  - Al acceder a `/admin`, el código verifica inmediatamente si estás autenticado.
  - Si NO lo estás, renderiza una pantalla de "Acceso Denegado".
  - Si SÍ lo estás, renderiza el Panel de Administración.


3. ESTRUCTURA ACTUAL DEL PANEL DE ADMINISTRACIÓN (/admin)
---------------------------------------------------------------------
Actualmente, el panel contiene una interfaz base preparada para conectarse a n8n o Strapi:
- Cabecera: Muestra un saludo dinámico ("Bienvenido, [nombre del usuario]").
- Métricas Simuladas: 3 tarjetas que muestran datos como "Predicciones Generadas", "Alertas Emitidas" y "Estado de API". (Ideal para que en el futuro las actualices consultando datos reales desde Strapi/n8n).
- Sección de Gestión Rápida: Un bloque reservado ("Funciones en desarrollo") donde se planea colocar botones o interruptores (Toggles) para Forzar Actualizaciones de IA o Cambiar estados manuales de pasos fronterizos.


4. IDEAS PARA INTEGRAR CON n8n EN EL FUTURO
---------------------------------------------------------------------
A) Modificar Datos (Ej: Forzar a "Cerrado"): 
   Puedes crear botones en el Panel Admin que hagan una petición HTTP (Webhook) hacia n8n. n8n recibe la orden, procesa la lógica, y usa su propio Token de acceso (API Token) para cambiar el registro en Strapi.

B) Validación de Seguridad:
   Si el frontend llama a un Webhook de n8n, puedes enviar el token `jwt` del usuario logueado en las cabeceras (Headers: `Authorization: Bearer <tu_jwt>`). Así, n8n puede validar con Strapi si la persona que ejecutó el Webhook realmente es un administrador válido antes de hacer cambios.

C) Cargar Métricas:
   Puedes crear un flujo en n8n que cuente cuántos registros hay en `senal_predictivas` o `incidentes` cada día, y guarde este resumen en una nueva tabla de Strapi llamada `metricas_sistema`. El panel `/admin` del frontend solo tendría que leer esa tabla.
